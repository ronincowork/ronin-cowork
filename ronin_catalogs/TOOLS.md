# TEJUN — tool list (executables that implement actions)

The TEJUN triad: **macros** (recipes the_owner invokes) are made of **actions**
(procedures, ACTIONS.md); where an action has a script, that script is a **tool** —
one call instead of hand-rolled choreography. Tools live in the repo's `ronin_bin/`,
which `setup.sh` puts on PATH — call them by bare name, never by a built path.
(`shim/tmux` is the exception below: it is PATH interception, not a command you type.)
Agents: PREFER the tool over performing the action by hand — the tool encodes the
safety steps (dial check, ghost-text rule, confirm-started) so you can't skip them.

| Tool | Implements (action) | Usage |
|---|---|---|
| `shim/tmux` | control-check | On PATH ahead of real tmux: denies writes/reads per the session dial and refuses dial flips, **for any CLI** (claude, codex, pi, scripts). The vendor-neutral enforcement point. |
| `shim/systemctl` | — | On PATH ahead of real systemctl: refuses to stop, restart or kill `tmux-server.service` while sessions are live — that unit owns every session on the box, so stopping it ends all of them at once. It never offers an override. Floor for every Agent, because an Agent sources no rc file and would otherwise reach `/usr/bin/systemctl` unguarded. This is a guard, not a restart route: the only Agent tool for restarting Ronin is `tejun-machine-restart`. |
| `tejun` | compile-macro | `tejun <macro>` → the recipe + every action it names + their tools, as one blob. Also starts step tracking at step 1. `tejun` with no args lists macros. Exit 3 = the macro names an undefined action. |
| `tejun-step` | step-through | `tejun-step start <macro>` → step 1; `tejun-step done` after each step → the next one; `where` / `stop`. Position lives on the tmux session. |
| `tejun-survey` | survey-machine | `tejun-survey [path]` → the **kind** of box first (physical / virtual machine + hypervisor / container) and its vendor, then cores, RAM, the disk on the filesystem holding `path` (default `$PWD`, never `/` unless that is where the work is), every real mount, and every store with its size. Read-only, no session touched, no dial. Exit 3 = no such path. Cited by `ronin_sops/data.md`, which carries no numbers of its own — capacity is measured, never written down. |
| `tejun-machine-restart` | restart-ronin | `tejun-machine-restart` — **no arguments**. Restarts Ronin (the app: grid, API, launcher) and nothing else; there is no unit to name. Sessions are untouched — they live in the tmux server, not in Ronin. Exit 4 = an argument was passed; exit 2 = Ronin does not run as a service on this box; exit 5 = it did not come back (report, do not retry in a loop). |
| `tejun-account` | survey-account | `tejun-account` (no args) → the owner display name (or `NOT SET`, when it is falling back to the login), the entitlement, the session max, and the config path. SETTEI's half; pair with `tejun-secrets` for which credential is in force. Read-only, prints no credential. Cited by `ronin_sops/accounts.md`. |
| `tejun-secrets` | survey-secrets | `tejun-secrets [path]` → the env files in a project, the key **NAMES** in each (never values — there is no flag for that), whether git tracks them, whether `.gitignore` covers them, and **which provider credential a launched agent would use** (resolution order, with the empty-`ANTHROPIC_API_KEY`-still-wins trap called out). `*.example` and friends report as templates, not alarms. Exit 4 = something is tracked and therefore already public; exit 3 = no such path. Read-only: never stages, writes, or edits `.gitignore`. Cited by `ronin_sops/secrets.md`. |
| `ronin-repo-init` | repository-initialize | `ronin-repo-init <existing-project-root>` → `INITIALIZED <path> — local repository only; no remote was assumed`, or `READY` when one already exists. It runs local `git init` only; it never creates the root or adds a remote. Exit 2 = bad argument. |
| `tejun-send` | send-to-session | `tejun-send <session> <message...>` → `DELIVERED` when it entered immediately, or `QUEUED … (message <id>)` when it cannot. Both are accepted outcomes: the durable Messages flow keeps checking safe delivery and exposes Try Again / owner-only Force. |
| `tejun-harakiri` | harakiri | `tejun-harakiri` — **no arguments**. Hands your pane to Ronin, which resolves the session and ends it. No output on success (you are gone). Exit 4 = a name was passed, or owner-dialled; exit 5 = Ronin unreachable (you are still here — report it, don't improvise). |
| `tejun-team` | team-roster | `tejun-team <team>` → the sessions on that team, one per line + dial. No arg → every team in play, with counts. Exit 3 = no such team. Reads tmux directly, so it answers even when Ronin isn't running. (`tejun-group` is the retired name and forwards here.) |
| `tejun-fork` | session-launch | **Launch one visible Ronin Agent by required `--name`.** An optional quoted instruction, `--team`, repeatable `--behaviour ways:<book>`, `--provider`, `--model`, or `--dial user|read|write` state only what was chosen. Omission inherits the caller's Campaign and first Team, then the Campaign and install launch defaults; blank Control falls back to read-and-write. It returns one `BORN` or `REFUSED` result and never types into a pane. |
| `tejun-session-set` | session-upsert | **One session, by name — read it, raise it, or change its facts.** The pair of `tejun-team-set`. Bare `tejun-session-set <name>` on a live name READS it (role, teams, 人, dial, root). A name nobody holds is BORN through the same launch resolver; with no `--team` the newborn joins the first team you are on. A live name with flags is updated in what you name. Use `tejun-fork` for the no-fuss Agent launch. |
| `tejun-team-set` | team-upsert | **Make a team, or change its facts — the rare door.** `tejun-team-set <team> [--objective <text>] [--root <project_root>] [--repos a,b] [--branch <b>] [--add s1,s2]` → `CREATED <team>` or `UPDATED <team>`. One upsert: a team with no roster is created from what you name, one with a roster is updated only in those fields. `--add` tags live sessions onto it (additive; a name not live is reported, the rest go through). You rarely need this — `tejun-session-set` puts a newborn on your team with no team named; come here to create a team or give it a brief worth inheriting. Exit 2 = bad arguments, 4 = refused, 5 = unreachable. |
| `tejun-wipeboard` | wipeboard-check, wipeboard-post | **Two bare forms are the whole ability.** `tejun-wipeboard` prints everything on your team's board you have not read, oldest first, then records the read; `tejun-wipeboard post [--to a,b|none] <text>` says something on YOUR TEAM'S board — no board name, the tool knows your team. An agent never handles an id, a timestamp, a cursor, a page or a file. `nothing unread …` (exit 0) when caught up or on no team — ordinary answers. **Quiet by default**: a bare post interrupts THE LEAD ALONE; `--to a,b` adds those, `--to all` is the explicit everyone, `--to none` interrupts nobody; an EMPTY `--to` is refused (`BAD-ADDRESSEE`, exit 2, nothing posted). Addressing decides who is INTERRUPTED, not who may read — every member still gets the post when they check. The dial is enforced by tejun-send; a failed notice never fails the post. A board NAME is only for a board that is not your team's (`… <board> post …`), and history is explicit and cursor-free: `… boards` · `… <board> read [n]` · `… <board> find <text>`. Posts are CLEARED after 48 hours, whoever has read them — a board is a transport, not a record. On several teams, bare post asks which (`WHICH-TEAM`, exit 2). Exit 2 = bad name/addressee/ambiguous team, 3 = no such board, no team, or not in a session, 1 = store unreachable or the read could not be recorded (those posts arrive again). |
| `tejun-teampage` | team-page-read, team-page-draft | **The team page your team is showing, and a draft of how it should look.** Bare `tejun-teampage` prints the view — your team's roster (who is on it, who is 人, which is you), then each tab on your team: which workspace is selected (the one the owner is typing in), which workspace shows YOU, and what each holds. `tejun-teampage <key=value …>` hands the page a draft; **what you omit stays as it is.** Words: `workspace1=<session>` or `me` · `workspace2=commons` · `commons:docs` (a tab: docs · wipeboard · config) · `commons:docs:<path>` (▧ Docs with that file open) · `cowork` / `cowork:<tab>` (the cowork commons: health · account · profile · roots · help · keypad) · `new` (the ＋ New session surface) · `terminal` (the seat back as it was) · `empty` · `count=2` / `count=4` (two workspaces around the roster, or four two-by-two — `workspace3`/`workspace4` are the lower cells, 1 over 3, 2 over 4) · `order=workspace2,roster,workspace1` (a column word is a stack; the roster goes left, centre or right) · `hidden=roster` · `shown=roster` · `hidden=none`. "Show the owner the doc I am on", from workspace 2: `tejun-teampage workspace1=commons:docs:<path>`. Read the view first so you know which workspace you are in; then arrange the page any way you like — it is the same `arrange()` the owner's own buttons call, no more and no less. Two tabs may show one team: the draft goes to the tab that shows you, else to every tab on the team. The dial applies as for `tejun-send` (`REFUSED`, exit 4). `NO-PAGE` (exit 0) = no tab is showing the team. `--team <t>` on several teams (`WHICH-TEAM`, exit 2). Exit 2 = bad draft, 3 = no session/team, 5 = Ronin unreachable. |
| `mika` | propose-and-confirm | `mika <job> "<request>"` → hands it to the house assistant, starting her if she is not up. Jobs: `system_help` (the default) · `project_root` · `new_session` · `system_config`, catalogued in `MIKA_MACROS.md`. `mika "<question>"` with no job named is help. **If a `+<job>:` from that catalog lands in your pane, run this — do not perform it yourself.** When she is already up it hands off to `tejun-send`, so the request is either `DELIVERED` or durably `QUEUED`; starting her prints `STARTED`, and exit 5 = Ronin unreachable. |
| `tejun-peek` | session-catchup | `tejun-peek <session> [lines=60]` → recent pane output, ANSI-stripped. DENIED if dial is 👤 user. |
| `tejun-recall` | recall-memories | `tejun-recall` → the memories this session should be handed, one file path per line, ordered (universal law first, then this project, then cross-project) and deduped; `--list` → kind + scope + summary per match; `--inline` → the composed text for a boot brief, budget-guarded and omitting LOUDLY when over. Axes come from the session's own project_root option and its LETTER's `role_family`/`session_role` (viewer-resolved), or from `--project_root` / `--role_family` / `--session_role`; the project axis also answers to the root's `memory:` keys. The two contextual axes ADD rather than override, so a role-scoped memory keeps reaching a session after its task moves on. No store yet is silence, not an error; a memory missing an axis is reported MALFORMED on stderr, never silently matched. See `docs/oboeru.md`. |
| `tejun-remember` | remember-lesson | `tejun-remember "<the thing>" [--tags a,b] [--kind rule/fact/pointer] [--summary s]` → one memory in the OBOERU store, frontmatter written for you; verdict `REMEMBERED <file>` + the scope it claimed. Axes you don't name are INHERITED from this session, never widened; `--any <axis>` widens deliberately. Exit 3 = cannot tell what this session is (name an axis); exit 4 = both axes wildcard, REFUSED — a memory matching every session is the system prompt, owner-only. See `docs/oboeru.md`. |
| `tejun-rireki` | session-catchup | `tejun-rireki <session> since` → everything the pane emitted since the owner's last message; `… text [KB]` → the tail as readable text; `… <session>` → what the tape holds (segments, marks, dial); no arg → every tape in play. Reads the tape file, so it answers for sessions with no tile open, and when Ronin isn't running. The strip is dumb by design — repaints are left in; Ronin's lens is the one that collapses them and labels the result as reconstruction. |
| `read_tegami` | read-letter | `read_tegami` → your letter; `--json` → just the block; `--rungs` → the positions a marker can point at, as they sit in the letter (a gate is `N`, a leg is `N.M`), with the current one flagged; `--session <name>` → another session's, refused at dial 👤. **No paths**: it resolves the pane's own session, viewer-safe. Exit 3 = no letter yet. |
| `write_tegami` | write-letter | `write_tegami` ← the json block on stdin, replacing your own ladder: `objective`, `session_role`, `ladder`, and `ladder_state` ("on tangent") when you are not walking it. Nothing else. **`role_family` is REFUSED in the block and carried through unchanged** — it is fixed at birth for the life of the session, and a change of role is a new session rather than a new value. `write_tegami --session <name> --at 2.3` (or `--at 4` for a gate, `--at none`) writes ANOTHER session's `at` and **only** `at` — one position, never json. `at` is a pointer at whichever rung is being worked on now, `{rung,leg}` as written so it can be checked by eye; a separate key from `status` because a pointer expressed as a status cannot move without asserting what it left behind. An agent save is REFUSED if it contains `at` and carries the existing value through, except when the save changes the ladder's SHAPE, where it resets to null. The read-modify-write happens inside the tool, atomically, so a caller never holds a block across a call and cannot revert the agent's authoring. **No dial check on `--at`** (owner law): the dial governs who may DRIVE a session, and pointing at a rung does not — a session on 👁 read is watch-only, and watching is exactly when you want to see where it is. Validates the SHAPE, never the claims; refuses `GATE` as a status (it is a rung kind) and the retired `asks`/`blocked`/`decided`/`handoff`/`plan`/`side_ladder`/`v` by name. Exit 3 = bad block, letter untouched. |
| `tejun-desk` | desk-open, desk-status, desk-sync, hand-in, desk-park | **Your desks — open, status, sync, hand in, park, recover.** `tejun-desk status` → one line per desk: clean/dirty · ahead (not handed in) · behind · pending update (by whom, overlapping which of your unsaved files) · last hand-in · BLOCKED. `tejun-desk hand-in [<repo>]` → `ACCEPTED <repo>:<branch> → <line> now <sha>` / `CONFLICT … files: …` (the lead adjudicates) / `STALE` (line moved repeatedly; re-run) / `REFUSED` (nothing ahead, or the line's worktree is dirty), then the sibling notices; `--assignment` does every desk. `tejun-desk sync` adopts the line (`ADOPTED` / `PENDING` when dirty / `CONFLICT`). `tejun-desk park [--unmount]` → `PARKED` (WIP kept, ahead count) or `DELETED` (tip already on the line). `tejun-desk parked`, `recover <repo> <branch> --session <s>`, `discard <repo> <branch> --yes`, `receipts [--line]`, `open <repo>`. Exit 0 done · 2 bad arguments · 3 `NO-DESK`/`NO-SESSION` · 4 `REFUSED`/not accepted · 5 `STUCK`. |

Rules for adding tools:
- A tool must implement a documented action — no orphan scripts. Action first
  (ACTIONS.md), tool second, then the action's entry points at the tool.
- Tools self-enforce the dial (they check @ronin-control before acting) so the
  sanctioned fast path is never a bypass of the guard hook.
- Small, zero-dependency bash; one-line verdicts; meaningful exit codes.
