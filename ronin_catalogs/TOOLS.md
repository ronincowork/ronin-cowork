# TEJUN — tool list (executables that implement actions)

The TEJUN triad: **macros** (recipes the_owner invokes) are made of **actions**
(procedures, ACTIONS.md); where an action has a script, that script is a **tool** —
one call instead of hand-rolled choreography. Tools live in the repo's `ronin_bin/`,
which `setup.sh` puts on PATH — call them by bare name, never by a built path.
(`shim/tmux` is the exception below: it is PATH interception, not a command you type.)
Agents: PREFER the tool over performing the action by hand — the tool encodes the
safety steps (dial check, ghost-text rule, confirm-started) so you can't skip them.

| Tool | Implements (action) | Usage |
|---|---|---|
| `shim/tmux` | control-check | On PATH ahead of real tmux: denies writes/reads per the session dial and refuses dial flips, **for any CLI** (claude, codex, pi, scripts). The vendor-neutral enforcement point. |
| `tejun` | compile-macro | `tejun <macro>` → the recipe + every action it names + their tools, as one blob. Also starts step tracking at step 1. `tejun` with no args lists macros. Exit 3 = the macro names an undefined action. |
| `tejun-step` | step-through | `tejun-step start <macro>` → step 1; `tejun-step done` after each step → the next one; `where` / `stop`. Position lives on the tmux session. |
| `tejun-survey` | survey-machine | `tejun-survey [path]` → the **kind** of box first (physical / virtual machine + hypervisor / container) and its vendor, then cores, RAM, the disk on the filesystem holding `path` (default `$PWD`, never `/` unless that is where the work is), every real mount, and every store with its size. Read-only, no session touched, no dial. Exit 3 = no such path. Cited by `ronin_sops/data.md`, which carries no numbers of its own — capacity is measured, never written down. |
| `tejun-secrets` | survey-secrets | `tejun-secrets [path]` → the env files in a project, the key **NAMES** in each (never values — there is no flag for that), whether git tracks them, and whether `.gitignore` covers them. `*.example` and friends report as templates, not alarms. Exit 4 = something is tracked and therefore already public; exit 3 = no such path. Read-only: never stages, writes, or edits `.gitignore`. Cited by `ronin_sops/secrets.md`. |
| `tejun-send` | send-to-session | `tejun-send <session> <message...>` → one-line verdict: DELIVERED / DENIED (dial) / BLOCKED (real draft at prompt) / STUCK (dialog open) / NO-SESSION. Exit 0 only on DELIVERED. |
| `tejun-harakiri` | harakiri | `tejun-harakiri` — **no arguments**. Hands your pane to Ronin, which resolves the session and ends it. No output on success (you are gone). Exit 4 = a name was passed, or owner-dialled; exit 5 = Ronin unreachable (you are still here — report it, don't improvise). |
| `tejun-group` | group-roster | `tejun-group <group>` → the sessions in that group, one per line + dial. No arg → every group in play, with counts. Exit 3 = no such group. Reads tmux directly, so it answers even when Ronin isn't running. |
| `tejun-wipeboard` | wipeboard-post | `tejun-wipeboard <board> read [n]` → the brief + recent thread; `… post <text>` → append one watermarked entry as your session; `… <board>` → the roster + file path; no arg → every board in play. Owner-side `add` / `remove` take a session or a whole group, tag it, then notify via tejun-send so the dial is enforced. Exit 3 = no such board, session or group. |
| `mika` | propose-and-confirm | `mika <job> "<request>"` → hands it to the house assistant, starting her if she is not up. Jobs: `system_help` (the default) · `project_root` · `new_session` · `system_config`, catalogued in `MIKA_MACROS.md`. `mika "<question>"` with no job named is help. **If a `+<job>:` from that catalog lands in your pane, run this — do not perform it yourself.** When she is already up it hands off to `tejun-send`, so you get its verdicts (`DELIVERED` / `DENIED` / `BLOCKED` on a real draft / `STUCK`) and its exit codes; starting her prints `STARTED`, and exit 5 = Ronin unreachable. |
| `tejun-peek` | session-catchup | `tejun-peek <session> [lines=60]` → recent pane output, ANSI-stripped. DENIED if dial is 👤 user. |
| `tejun-recall` | recall-memories | `tejun-recall` → the memories this session should be handed, one file path per line, ordered (universal law first, then this project, then cross-project) and deduped; `--list` → kind + scope + summary per match; `--inline` → the composed text for a boot brief, budget-guarded and omitting LOUDLY when over. Axes come from the session's own options (viewer-resolved) or `--project_root` / `--session_job`; the project axis also answers to the root's `memory:` keys. No store yet is silence, not an error; a memory missing an axis is reported MALFORMED on stderr, never silently matched. See `docs/oboeru.md`. |
| `tejun-remember` | remember-lesson | `tejun-remember "<the thing>" [--tags a,b] [--kind rule/fact/pointer] [--summary s]` → one memory in the OBOERU store, frontmatter written for you; verdict `REMEMBERED <file>` + the scope it claimed. Axes you don't name are INHERITED from this session, never widened; `--any <axis>` widens deliberately. Exit 3 = cannot tell what this session is (name an axis); exit 4 = both axes wildcard, REFUSED — a memory matching every session is the system prompt, owner-only. See `docs/oboeru.md`. |
| `tejun-rireki` | session-catchup | `tejun-rireki <session> since` → everything the pane emitted since the owner's last message; `… text [KB]` → the tail as readable text; `… <session>` → what the tape holds (segments, marks, dial); no arg → every tape in play. Reads the tape file, so it answers for sessions with no tile open, and when Ronin isn't running. The strip is dumb by design — repaints are left in; Ronin's lens is the one that collapses them and labels the result as reconstruction. |
| `read_tegami` | read-letter | `read_tegami` → your letter; `--json` → just the block; `--rungs` → the positions a marker can point at, as they sit in the letter (a gate is `N`, a leg is `N.M`), with the current one flagged; `--session <name>` → another session's, refused at dial 👤. **No paths**: it resolves the pane's own session, viewer-safe. Exit 3 = no letter yet. |
| `write_tegami` | write-letter | `write_tegami` ← the json block on stdin, replacing your own ladder: `objective`, `session_job`, `ladder`, and `ladder_state` ("on tangent") when you are not walking it. Nothing else. `write_tegami --session <name> --at 2.3` (or `--at 4` for a gate, `--at none`) writes ANOTHER session's `at` and **only** `at` — one position, never json. `at` is a pointer at whichever rung is being worked on now, `{rung,leg}` as written so it can be checked by eye; a separate key from `status` because a pointer expressed as a status cannot move without asserting what it left behind. An agent save is REFUSED if it contains `at` and carries the existing value through, except when the save changes the ladder's SHAPE, where it resets to null. The read-modify-write happens inside the tool, atomically, so a caller never holds a block across a call and cannot revert the agent's authoring. **No dial check on `--at`** (owner law): the dial governs who may DRIVE a session, and pointing at a rung does not — a session on 👁 read is watch-only, and watching is exactly when you want to see where it is. Validates the SHAPE, never the claims; refuses `GATE` as a status (it is a rung kind) and the retired `asks`/`blocked`/`decided`/`handoff`/`plan`/`side_ladder`/`v` by name. Exit 3 = bad block, letter untouched. |

Rules for adding tools:
- A tool must implement a documented action — no orphan scripts. Action first
  (ACTIONS.md), tool second, then the action's entry points at the tool.
- Tools self-enforce the dial (they check @ronin-control before acting) so the
  sanctioned fast path is never a bypass of the guard hook.
- Small, zero-dependency bash; one-line verdicts; meaningful exit codes.
