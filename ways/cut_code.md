# Cut code

Use this way of working when there is an approved plan and you want it implemented. Its
remit is to build from that plan, treating the plan as the contract for the change.

The Agent reads the plan first and works through it leg by leg. Claims are backed by
scoped evidence, unfinished or deliberately untested work is named, and decisions come
back to you instead of being guessed. Finished items leave the living plan as the work
lands.

In a managed repository, coherent checkpoints are committed privately and coherent legs
are handed in to the Team line. A commit preserves work; a hand-in offers it to the Team;
Team promotion is the lead's act. The Agent does not use Git push to publish desk work or
run the full repository BYOIN at commit or hand-in.
