# Mac Fortification — WIP buildout

## Settled outcome

A stock supported macOS install can set up, operate, inspect, update, roll back, and restart Ronin using its installed LaunchAgent. The browser reports measured state without inventing Linux facts. A restart or update is called safe for live sessions only after a real Mac proves the tmux server and an existing session survive it. Linux behavior remains covered.

This is a plan, not a claim that the Mac journey has passed. The `#109` Restart route and host tool fix is on dev; the live Mac session-survival gate remains open. The `#98` Installations refresh is also on dev and updates the parent stone and Setup zone after successful `/api/installed` reads; it does not restart Ronin.

## Severity of concern

| Severity | Concern and evidence | Required result |
|---|---|---|
| **High** | Session custody across `launchctl kickstart -k` is unproved. macOS has no separate `tmux-server.service`; `bin/ronin-update` explicitly says tmux daemonizes out of Ronin's LaunchAgent but does not promise survival. The Restart UI no longer makes that promise. | On a disposable Mac installation, start a session, record the tmux server and session identities, restart from Setup, and verify that both identities and the live process persist while Ronin's `startedAt` changes and the tile reconnects. Repeat through update and rollback. If tmux dies, stop treating restart as routine and give it independent, proven custody before shipping a safety claim. |
| **High** | `bin/ronin-update` compares `readlink -f` results for the loaded job's workdir and `current`. On a Mac where both calls fail or produce empty output, equality can falsely say the job serves this release, then restart the wrong job after a swap. Several Agent tool wrappers and `ronin_bin/tool-count.sh` also depend on `readlink -f`, so a stock Mac may fail before the command body. | Prove stock `/usr/bin/readlink -f` behavior on each supported macOS version; replace unsupported assumptions with one canonical, checked path-resolution operation. Empty or failed resolution must never establish equality. Test a loaded job serving this home, a different home, missing paths, and both-resolution failure. Run representative `ronin-host`, `work-record`, `edges`, and `worktree-desk` commands on stock Mac. |
| **Medium** | Services `machine/reading.ts` falls back to `os.freemem()` for available memory and marks swap unavailable while returning zero totals. Cowork's `ramrpm.js` and `machine-panel.js` still render that zero as “no swap”; `libexec/ronin-host-inspect` also says “none” when `/proc/meminfo` is absent. These are misleading macOS health claims. | Measure Mac memory headroom and swap with Mac-supported sources, or show an explicit unknown state. Propagate the distinction through the Services response, Cowork UI, and host inspection. Verify representative free, pressure, swap-enabled, and unavailable readings. |
| **Low** | Services `machine/watch.sh` is Linux-oriented, and `bin/ronin-doctor` has `timeout`, `readlink -f`, and `journalctl` paths that may not fit a stock Mac. `ronin_bin/machine-settings` uses `sha256sum` in Mika confirmation; updater checksum code already has a `shasum` fallback. | Inventory stock command availability (`readlink -f`, `timeout`, `sha256sum`), make each supported diagnostic/tool command work or clearly report unsupported scope, and give launchd-specific recovery advice where appropriate. The optional Mac machine watcher may be omitted; if machine status is offered, its UI and host inspection must not claim “no swap” from an unknown reading. |

## Cuts in dependency order

1. **Establish a stock Mac baseline.** Record macOS version, CPU architecture, shell/tool versions, installed LaunchAgent label and domain, serving workdir, and whether `readlink -f`, `timeout`, and `sha256sum` exist. Use a disposable user or machine and the supported installer. This evidence decides which portability assumptions actually fail.
2. **Make path identity trustworthy.** Cowork owns `bin/ronin-update`, setup, `ronin_bin` wrappers, and host/doctor tools. Centralize checked canonical-path resolution, preserve symlink semantics for `current`, and reject empty or failed comparisons. Prove the updater chooses restart only for the job serving its home. Fix tool entry points that cannot start on a stock Mac.
3. **Prove or repair restart custody.** Exercise installed Setup Restart, `ronin-host restart`, update, and rollback with a live disposable tmux session. Confirm the installed LaunchAgent marker arrives in the server, manual `npm start` refuses the installed-service Restart route, launchd restarts the intended job, Ronin health returns, and the same tmux server/session remains. If survival fails, gate both the macOS restart/update safety claim and the restart-required Services flow until independent tmux custody is designed and verified. A manual `launchctl` command is not a safe fallback.
4. **Make machine readings honest.** Services owns canonical `machine/reading.ts` and `machine/watch.sh`; Cowork's `src/services/` is generated placement. Cowork owns `public/js/ramrpm.js`, `public/js/machine-panel.js`, and `libexec/ronin-host-inspect`. Agree on a response shape that distinguishes zero from unavailable, then align readings, UI, and inspection. The optional Mac watcher can remain unsupported; any offered machine status must be truthful. Apply Services changes in its matching desk and run its `bin/verify --cowork <matching-worktree>` cross-check.
5. **Finish Mac diagnostics and user guidance.** Audit doctor and tool messages for Linux commands and unsupported assumptions. Document actual Mac install, restart, update, rollback, and failure recovery in the owning usage and construction pages. Keep Linux instructions intact.

## Checks, gates, and finish condition

- Focused unit tests cover path-resolution success/failure, service identity, legacy Linux unit selection, machine-data unknown states, and UI wording. Run shell syntax and TypeScript checks for changed surfaces. The Team lead owns the combined `npm run verify` gate; Services work also runs its matching cross-repository gate.
- **Mac gate:** a fresh stock macOS install completes the full Setup to working Agent journey, tool entry points run without added GNU utilities, and Restart/update/rollback preserve a live tmux session or the custody design is changed and verified. Capture exact OS, installed artifact, job label/domain, before/after PIDs and tmux identity, `startedAt`, and health result. A simulated launchd test is useful but does not close this gate.
- **Release gate:** no Mac safety or health claim is published from Linux-only evidence. The buildout is finished when the above Mac gate passes, the remaining concerns are resolved or explicitly scoped out with truthful UI/docs, focused checks and the lead's combined gate pass, and the standing contracts describe the shipped behavior. Then remove this WIP file.

## Rough effort for planning
