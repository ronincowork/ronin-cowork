The shape

One app, one gate, two suppliers of routes

Cowork never imports service code. src/index.ts scans src/services/ at boot, calls each register(sockets), and then mountServiceRoutes(app) attaches whatever they asked for — after core's routes, which is safe only because every service path is disjoint from every core path. A service that fails to load is logged and skipped; the grid stays up and its paths 404.

GET · POST /api/campaignsThe durable record of each body of work — campaign_config, one JSON per campaign in the user-scope campaigns store. The list carries archived records too (?state=active is the ordinary filter) in ONE deterministic order: created_at, then id to break a tie. An empty list is an answer, not an absence — a client paints its empty state on [] and synthesizes a fallback only when this route is unreachable. POST saves the campaign and stops: it writes one record, returns it whole so the caller can select the id without a second round trip, and creates no Cowork, no team_roster, no project_root and no session — true by construction, because the module imports none of those stores. 409 when the id is taken.
GET · PUT /api/campaigns/:id
POST /api/campaigns/:id/archive		One campaign: read, edit the stated keys, archive. id and created_at are refused BY NAME on an edit rather than ignored — the first is what every campaign_id points at, so moving it would be a migration and not a save; the second is provenance and list order, never a settable "default campaign". Archiving hides and kills nothing: no session stops, no desk is dropped, and PUT with state: "active" is the way back. There is no DELETE — nothing on a button deletes a record other objects still point at. docs/campaigns.md.
GET · POST /api/team-rostersThe durable half of every team — the League list (zero-member teams included, with wipeboard_exists) and Build Team's create. A roster holds objective and launch defaults, and refuses a member list or lead field BY NAME: membership is derived from the live sessions, always.
GET · PUT · DELETE /api/team-rosters/:nameOne roster: read, edit its readable metadata as a unit, or dissolve it. The snake-case Team ID is its stable address and cannot be renamed; the readable title is editable. Dissolving deletes the roster only; the wipeboard reverts to a custom board, because nothing on a button deletes a file. A blank field is written as — so the file reads as a page; the store reads that mark back as the blank it stands for.
GET · POST /api/team-templates
DELETE /api/team-templates/:name		User-scope New Team draft templates. Saving clears Team identity and transaction state; selecting one only prefills New Team and never launches it.
GET · PUT /api/sessions/:name/teamsThe one Agent-owned Team membership list. Every name must identify an active durable Team roster. Adding or removing a name adds or removes that membership; the roster stores no members.

The file editor — the ▧ Docs tab, and its one deliberate hole

EndpointWhat it does
GET /api/file?path=Read one file by absolute path. 404 rather than an empty editor when it moved.
PUT /api/file?path=Write it back. Body is text/plain, 8 MB — load-bearing: the global JSON parser's 100 kb limit would 413 a large document before the handler saw it. Refuses to create: a path that no longer exists means the file moved.
GET /raw/<absolute path>The file as itself, with its own content-type — so a listed .html renders in the ▧ Docs pane's frame and opens in a tab from ↗ (2026-08-26). Path-shaped, not a query, so a page's relative assets resolve through the same door. Same absolute-path rule and no-filter ruling as /api/file.

The one place with no allowlist /api/file has no path containment, no realpath check and no extension filter, and that is a ruling rather than an oversight: Ronin binds to the tailnet, and every agent on the box already has a shell. A filter here would guard nothing while costing a rule to maintain. No mtime precondition either — whole-file write, last write wins, and retyping a paragraph is a cheaper failure than another moving part.

ronin-services

The paid layer's 21 endpoints

Each service is one folder shipping one register(sockets) entry. Absence is never an error: no michi means no ladder panel, no rireki means every tile is locked 🔒 and the switch greys out. The client learns which are present from /api/version's services list, so it draws an absent surface inert instead of fetching into a 404.

michi — the session ladder (TEGAMI)

Read-only by construction: there is no write verb here and there never will be one. The agent owns the letter file, and the owner answers a gate by typing into the pane.

EndpointWhat it does
GET /api/sessions/:name/tegamiThe parsed ladder — objective, session_role, the derived teams block, rungs, legs, marker, docs.
GET /api/sessions/:name/tegami/rawThe letter verbatim: the markdown shell and the JSON block exactly as the agent left them.

rireki — the session record and the 🔓 unlocked tape

Also the sole owner of the stream handler plugged into the /pty socket — see the websockets below. The dial is the owner's hand only; agents read it and report.

EndpointWhat it does
GET /api/sessions/:name/rirekiThe dial state, the tape head, and whether a tape exists at all.
POST /api/sessions/:name/rirekiTurn recording on or off. Turning it back on sweeps immediately.

counting / tomodachi — usage stats, and the dictation relay

The beacon is the only path client-side probes have to the server. Fire-and-forget: 204 always, allow-listed ids only, and an unknown id writes a FAULT rather than being silently dropped — a typo'd probe shows up on the tab instead of quietly counting nothing.

EndpointWhat it does
POST /api/transcribeDesktop push-to-talk: raw audio (25 MB cap, any content-type) relayed to the host Whisper service, transcript returned. 503 when SCRIBE_URL is unset. The hotwords prompt rides as a query param, not a header — a header must be latin-1, and these are the owner's own words.
POST /api/tomodachi/eventThe client beacon. 1 kb, 204 immediately.
POST /api/tomodachi/collectThe other end of the drop — this install acting as a collector. 404s unless TOMODACHI_COLLECT_KEY is set, so a normal install is not an open write endpoint.
GET /api/tomodachi/stats?window=The ▦ Stats tab's one read: today · week · month · all, folded over daily files.

koshi — the house agent, and which outlet each incarnation asks

No keys pass through here. An incarnation may name the env var that holds its key, never a key.

EndpointWhat it does
GET /api/koshiOutlets, incarnations, paces, current choices — and whether the watcher is actually running, because "I moved the slider and nothing happened" is otherwise indistinguishable from "it has been down for two days".
POST /api/koshi/restartKill and start the watcher. Declared before the parameterised route — Express matches in definition order, so the other way round this reads as an incarnation named "restart".
POST /api/koshi/:incarnationSet one incarnation's outlet, model and pace. One at a time, because that is what a dropdown changing does and a bulk save invites a stale tab to overwrite a fresh one. An unknown outlet is refused rather than stored.

koe — the dictation vocabulary

Whole-file in, whole-file out. No per-term CRUD on purpose: it is a text file, and an API over a list of words would be more machinery than the thing.

EndpointWhat it does
GET /api/hotwordsTerms, the full text, the assembled prompt, and own — is this list yours yet, or still Ronin's shipped one? Hotwords is copy-on-write rather than an entry-merge.
POST /api/hotwords/addAdd one term; returns the resulting list so the client renders what came back.
POST /api/hotwords/removeRemove one.
PUT /api/hotwordsReplace the whole file.

gbrain & koshi_weights — the installable-service shape

Both follow install-contract.md: five files, one register, and a three-route API — status · install · uninstall. gbrain is UI-fronted (a Load button); koshi_weights is headless — reached by a POST, a curl or a Mika macro, and also run as gbrain's leg 0. Nothing in cowork ever presses these itself.

EndpointWhat it does
GET /api/gbrainThe snapshot: installed, dimensions, degraded reason, known integrations, observed-at.
POST /api/gbrain/installRuns the service's own setup.sh. 409 if a run is already going.
POST /api/gbrain/uninstallRuns uninstall.sh, which says what it kept — the owner's knowledge is never deleted from a button.
GET /api/koshi_weightsSame status shape, for the local weights.
POST /api/koshi_weights/installSame setup.sh gbrain's leg 0 runs — neither path is special.
POST /api/koshi_weights/uninstallReverses it.
Not HTTP

The websockets, the connector, and the shelf

Two websockets, both through the same gate

SocketProtocol
/pty?session=&cols=&rows=Faucet A — the attach mirror. Server sends {t:'ready',session,viewer}, then raw output; {t:'exit'} at the end. Client sends {t:'i',d} input, {t:'r',cols,rows} resize, {t:'bottom'} jump, {t:'hist'} → {t:'hist',d}. Scrollback stays server-side.
/pty?mode=streamThe 🔓 tape. Handed straight to rireki's handler via the connector's setStreamHandler; it reads the tape and never touches tmux. No service → an error frame telling the client to fall back to 🔒.
/eventsOne per browser page, not per tile. Pushes {t:'sessions',list} on connect and whenever membership or a session's mark changes, off one tmux list-sessions every 2s — skipped entirely while nobody is listening. Attach and note flapping are deliberately not events.

Both are compressed above 4 kb: a tape-fed tile opens with megabytes of reconstructed history, terminal text compresses roughly tenfold, and a phone on a weak connection is exactly who is waiting for it.

The connector — the API that crosses the repo boundary

Not HTTP at all: eight typed sockets in sockets-contract.ts, versioned as CONTRACT_V = 1. A service compiles against these shapes, so a mismatch fails tsc in the services repo rather than at a tenant. The written meaning lives in connector-contract.md, and that doc wins any argument the type names start.

SocketWhat plugging it buys you
registerBootYour own timers and janitors, stopped at shutdown.
onSessionWillBornPre-create: the name is claimed, the session does not exist yet. rireki resets a reused name's stale tape here.
onSessionBornEvery birth path, after the session exists.
addBirthLinesLines appended to the opening brief. Empty string = silent.
onSessionEndA session is being deleted; the key was resolved before the kill.
addRowFieldsFields on /api/home rows. {} = silent.
addRoutesThe 21 endpoints above. Called once with the Express app.
setStreamHandlerThe 🔓 tape handler. One owner (rireki); absent = locked view only.

The agent shelf — the surface agents actually type at

Agents on the box do not post JSON. They run bare-name bash tools on ronin_bin/, which is on PATH ahead of everything but the guard shims. A TEJUN tool is one that implements a cataloged action in one call — and it self-enforces the dial, so the fast path is never a bypass of the guard hook.

ToolWhat it is
write_tegami · read_tegamiThe letter: replace your own ladder from stdin, or move another session's marker with --at 2.3. Also --on_tangent / --on_track and --doc / --undoc.
tejun-sendDeliver a message into a session: dial check, ghost-aware pre-send check, literal text then a separate Enter, confirm-started with one retry. One-line verdict, meaningful exit code.
tejun-step · tejun-survey · tejun-peekMove through work, look around, look at one thing.
tejun-team · tejun-wipeboardTeams (leads marked 人) and shared boards.
tejun-recall · tejun-rememberThe owner's knowledge, in and out.
tejun-rireki · tejun-harakiriThe record, and ending yourself.
tejun-account · tejun-secretsAccounts and credentials.
mikaRonin's own assistant.

Beside it, by audience: bin/ is the owner's own commands (ronin-doctor, ronin-deploy, ronin-passwd, …), libexec/ is typed by nobody — invoked by systemd, by git hooks, by tmux.

Outbound

The three calls Ronin makes out, and what happens when they are unset

  • The OpenAI-shaped wire — koshi's outlets. Exactly one file in the whole tree names a vendor (koshi/outlet-http.ts), pinned there by check-kyokai, so a second provider is a sibling leaf rather than a rewrite. Structured output is enforced at the API, not recovered from text. Timeouts are per outlet, measured: 45 s external, 120 s local weights — a truncated call is indistinguishable from "the model said I don't know", which is the one failure nobody can see from outside.
  • SCRIBE_URL — the host Whisper service behind /api/transcribe. Unset → 503 and /api/health reports transcribe:false, so the button never appears.
  • TOMODACHI_URL — the stats drop. Unset → the whole thing is off, counting continues locally, nothing breaks. No retry daemon, no queue, no schedule; a failed post is stated on the ▦ Stats tab and retried at the next natural roll-up. What is sent is byte-identical to what is kept in sent/, so "what have you ever sent about me?" is answerable offline, forever, without asking anyone.
