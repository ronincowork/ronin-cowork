The idea

Assembled from several places, and that is the design.

One record, three sections. Everything in it arrived one of three ways, and keeping those apart is what stops a config file lying — but they read as one document, because which file a value happens to sit in is our problem, not yours.

set

you typed it

Your name, this box, your projects, how work gets a model, your services decision. The only half that persists.

observed

found, never typed — the machine, and what is in it

Hardware, OS, versions, routes, which agents exist. Never written down — with an observed_at so you know how fresh it is.

status

follows from both

What is healthy, what is missing, what is running. Computed on read, never stored.

One writer, writing one half. No cache, no sync, no reconciliation — which is where the simplicity actually lives.

Remit is the line you pick a project from in a list — it already exists in the roots file and nothing was surfacing it. Where is free text by ruling: you know where your box is, the box does not.

Two things wearing one word

agents.sessions is what a new session launches as — a CLI in a tile. Per-project defaults exist; an install-level one does not, which is why a project naming none falls back to a bare claude that matches no launch-table row.

agents.jobs is the house's own model-fed jobs — one question, one answer, over an API. Not a session, so each needs a key. The record holds the variable's name; the value stays in .env and appears nowhere.

5 · The subscription

Four fields, and the round trip that fills them.

Press get services, accept the terms, give an email. We send a link; you click it; the id is minted against that address and comes back as a code you paste in. From then on every usage drop carries the id, so we can match usage to the account that accepted the terms.

Two properties worth keeping in view, because they shape the field: the id is not a key — it unlocks nothing on the box, and our collector treats it as a claim to match rather than proof. And it cannot ride inside the tarball, because one artifact with one checksum is what makes a release identifiable.

The full reasoning — why gating the entitlement rather than the bytes, and the AGERU egress argument behind the pasted code — lives in plans/SETTEI.md Part III. It does not need to be re-read to look at the record.

6 · Settled, and what is left

Five rulings in. Judgment calls out.

Ruled. The surface is a Commons tab, not the gear · machine.where is free text · the subscription records the email beside the id · the id arrives as a pasted code · the entitlement records only and enforces nothing on the box · the session cap appears in both ⚙ Setup and ⌂ Roster over one route.

Where does the line fall between observed and set?

Provider and hypervisor come free from the DMI table. Region does not — it needs a cloud metadata call, so it is machine.where in your words instead. Instance size is the same shape: cores and RAM are observed, but "CX43" is not knowable without asking Hetzner.

Working rule: observe what the kernel already knows; ask you for the rest. No outbound call belongs in a record that renders on page load.

How much service health belongs here?

Registered is cheap and honest. Working is not — proving Koshi answers means spending an API call, and a record that costs money to render is a record nobody opens twice.

Recommendation: report registration and configuration, never liveness. A "check it now" button is a different thing and can come later.
