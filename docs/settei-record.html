The Settei Record

The one object, written out — filled with this machine's real values, so every claim can be checked. Each leaf carries its provenance — typed · found · derived — because provenance is all a view needs to render a leaf: an input, a fact line, or a task. This page is the schema the code answers.

how to read it

Three provenances, one object

typed — the owner said it · the only half persisted found — a scan answered it · per read, never stored derived — follows from the other two · computed away

In code: set / observed / status on GET /api/settei (src/settei.ts), plus the needed family still to build. One call, one answer, no writes. No route serves the underlying file — ronin.json also holds the token-signing secret, so the record is assembled from named keys, never the document.

the rules

What the record promises

  • Only typed persists. Found and derived are computed per read and carry observed_at; a stored measurement is a lie waiting to happen.
  • Secrets are presence, never value — key_env is a name, keys is a boolean, and there is no path from this record to a value in either direction.
  • A fallback in force is visible — typed null beside derived "glen3", so a default is never passed off as an answer.
  • Absent means absent, never missing — a CLI this machine could have reads installed: false, not a dropped key; a section that predates its key stays quiet.
  • Derived costs nothing to render — registration and configuration, never liveness; a record that spends an API call to draw itself is a record nobody opens twice.
